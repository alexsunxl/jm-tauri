pnpm install

pnpm build

## 阅读页图片处理阶段与日志建议
阅读页图片处理包含两步：请求/下载图片 + 切割重组（descramble）。相关代码位置：
- 前端队列/调度：`jm/src/pages/ReadingPage.tsx`（`wanted` 队列、`pump` 并发处理、`api_image_descramble_file` 调用）
- 前端解码状态：`ProcessedImage` 组件（直连图像加载、错误/重试）
- 后端解码：`jm/src-tauri/src/lib.rs`（`api_image_descramble_file` → `descramble_image_bytes_with_cancel`）

是否在 UI 拆分显示两个阶段，建议按耗时判断：
- 总耗时 < 300ms：合并为“处理中”，不拆分
- 300–800ms：默认合并，调试/高级信息中展示细节
- > 800ms 或明显卡顿：UI 可拆成“下载中 / 重组中”

为后续日志分析与导出准备的数据建议（每张图片）：
- 队列进入时间、请求开始/结束时间、重组开始/结束时间、总耗时
- 是否来自缓存（若可判断）、图片索引、章节/aid、分割参数 num
- 失败类型、错误码/错误消息、重试次数

汇总与导出建议：
- 按章节/设备/网络类型聚合：P50/P95/P99、失败率、重试次数分布
- 重点关注“重组阶段耗时占比”和“失败类型聚类”，便于定位瓶颈

### maxConcurrency 选择建议
并发数（`maxConcurrency`）决定同时处理多少张图片，平衡“总耗时”和“阅读流畅度”。经验建议：
- **阅读体验优先（10 页范围内尽快就绪）**：移动端建议 3（重组较重时可降到 2）
- **总时间优先（全章尽快完成）**：桌面端可 5–8，中端手机 3–4，低端机 2–3

### 网速自适应慢启动

策略常量集中在 `jm/src/reading/loadGovernor.ts` 的 `READER_NETWORK_POLICY`：

- `windowMs = 5000`：观察最近 5 秒，首个完整窗口确认速度前保持串行。
- `serialBelowBytesPerSecond = 128 * 1024`：窗口下载速度不高于 128 KiB/s 时降为串行。
- `parallelAboveBytesPerSecond = 384 * 1024`：窗口下载速度达到 384 KiB/s 时允许恢复并发。
- 两个阈值之间保持现有状态；每次切换后重新观察完整窗口，避免旧样本引发反复切换。

Rust 下载按块读取，通过 IPC Channel 每约 250ms 回报实际字节增量，开始时间包含建立请求及等待响应的时间。速度按窗口内所有下载的总字节数 / 至少一个请求正在下载的时间计算，同时下载的重叠时间只计算一次；缓存命中、图片重组、磁盘写入及无下载时段均不参与测速。

所有连续阅读章节共用一个并发预算。串行模式优先加载当前章节，空闲后再加载相邻章节；已在途的任务自然完成，不因降速中断。恢复并发后沿用逐步爬升和错误退避，并受用户设置的最大并发数限制。每 250ms 检查一次窗口，因此请求长时间没有数据时也会降速，不必等它成功或失败。无下载超过一个窗口后，下一次加载重新从串行观察，避免沿用过期的高速判断。

网络采样与可取消的等待封装在 `jm/src-tauri/src/reader_network.rs`。等待响应头和正文数据时均每 250ms 检查阅读会话的取消标记，切换章节或离开页面后可及时终止停滞的旧请求，释放共享名额。
